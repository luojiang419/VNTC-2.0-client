# 一键域名反代 Studio 公网部署与更新手册

## 说明

本文当前包含两种已经验证成功的公网接入方式：

- 方式 A：`服务器直接部署项目方式`
  - 指项目代码、进程和服务都直接部署在公网服务器上
  - 当前 `lwai.ee2x.cn` 就属于这一类
- 方式 B：`FRP反代添加方式`
  - 指服务实际跑在本地电脑或内网机器上
  - 先通过 `frp` 映射到公网服务器端口
  - 再由 OpenResty 将该端口转为子域名访问
  - 当前 `lm.ee2x.cn -> 64.90.17.178:12345` 属于这一类

## 6. 方式 B：FRP反代添加方式

### 6.1 将本地服务转为子域名访问

适用于：

- 服务实际运行在本地电脑或内网机器
- 已通过 `frp` 映射到公网服务器某个端口
- 当前已能通过 `http://64.90.17.178:12345` 这一类公网 IP 加端口访问
- 现在希望改成子域名访问，例如 `https://lm.ee2x.cn`

典型链路：

- 本地服务：`http://127.0.0.1:1234`
- `frpc` 映射后：`http://64.90.17.178:12345`
- OpenResty 子域名反代：`https://lm.ee2x.cn` -> `http://127.0.0.1:12345`

这套方案的核心思路与当前站点完全一致：

- 先让服务在服务器上有一个可访问端口
- 再让 OpenResty 用子域名去反代这个端口
- 最终对外只暴露 `443/80`，不再让客户端直接记 IP 和端口

#### 6.1.1 DNS 解析

先在域名服务商控制台增加子域名解析：

- 记录类型：`A`
- 主机记录：例如 `lm`
- 记录值：`64.90.17.178`

完成后，目标访问地址变为：

- `https://lm.ee2x.cn`

如果你的客户端是 OpenAI 兼容接口，一般实际填入：

- `https://lm.ee2x.cn/v1`

#### 6.1.2 `frp` 端口映射

如果本地服务监听的是：

- `127.0.0.1:1234`

则 `frpc` 可以映射成服务器上的：

- `64.90.17.178:12345`

示例 `frpc.toml`：

```toml
serverAddr = "64.90.17.178"
serverPort = 7000

[[proxies]]
name = "lmstudio-api"
type = "tcp"
localIP = "127.0.0.1"
localPort = 1234
remotePort = 12345
```

验证方法：

```bash
curl http://64.90.17.178:12345
```

如果是 OpenAI 兼容接口，可进一步验证：

```bash
curl http://64.90.17.178:12345/v1/models
```

#### 6.1.3 OpenResty 子域名反代

参考现有 `lwai.ee2x.cn` 的做法，新建一个单独站点配置，例如：

- `/opt/1panel/www/conf.d/lm.ee2x.cn.conf`

示例配置：

```nginx
server {
    listen 80;
    server_name lm.ee2x.cn;

    location ^~ /.well-known/acme-challenge {
        allow all;
        root /usr/share/nginx/html;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}

server {
    listen 443 ssl;
    http2 on;
    server_name lm.ee2x.cn;

    ssl_certificate     /www/sites/lm.ee2x.cn/ssl/fullchain.pem;
    ssl_certificate_key /www/sites/lm.ee2x.cn/ssl/privkey.pem;

    client_max_body_size 100m;
    add_header Strict-Transport-Security "max-age=31536000";

    location / {
        proxy_pass http://127.0.0.1:12345;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
        proxy_request_buffering off;
        proxy_read_timeout 3600;
        proxy_send_timeout 3600;
    }
}
```

说明：

- 这里的 `12345` 对应的是 `frp` 暴露在服务器上的端口
- 如果 OpenResty 容器内无法访问 `127.0.0.1:12345`，可临时改成 `http://64.90.17.178:12345` 排查
- 若改成公网 IP 能通，说明需要根据 1Panel/OpenResty 的网络模式调整宿主机回源地址

配置完成后执行：

```bash
container=$(docker ps --format '{{.Names}}' | grep '^1Panel-openresty-' | head -n 1)
docker exec "$container" openresty -t
docker exec "$container" openresty -s reload
```

如果你是通过本仓库里的“子域名反代 Studio”来做远程发布，当前正确的 1Panel 相关设置应为：

- `OpenResty 配置目录`：`/opt/1panel/www/conf.d`
- `证书根目录`：`/www/sites`
- `OpenResty 检测命令`：自动探测 `1Panel-openresty-*` 容器并执行 `openresty -t`
- `OpenResty 重载命令`：自动探测 `1Panel-openresty-*` 容器并执行 `openresty -s reload`
- 如果服务器 SSH 未开启 SFTP 子系统，软件当前版本也可自动回退为普通 SSH 命令写文件
- 如果 `FRP` 远端端口已经提前打通，而这次只需要“端口转子域名”，可将：
  - `FRP 配置输出` 临时填为 `/tmp/subctl-frpc.generated.toml`
  - `FRP 重载命令` 留空
  - 这样软件仍可完成 OpenResty 写出、检测、重载与公网检查
- 如果映射协议为 `https`，建议让 `80` 端口只负责 `301 -> https`
- 同时在 `443` 响应中加上 `Strict-Transport-Security`
- 否则即使证书本身有效，浏览器也可能因为同域名仍允许直接走明文 `http` 而提示“不安全”

#### 6.1.4 证书处理

子域名要让手机 App 正常访问，建议必须上 `HTTPS`：

- 可在 1Panel 里给 `lm.ee2x.cn` 申请 Let's Encrypt 证书
- 或沿用当前站点同样的证书申请与续期方式

不要长期使用：

- 纯 `http`
- 自签名证书

否则手机 App 可能直接拒绝连接。

#### 6.1.5 手机客户端填写方式

如果该本地服务是 LM Studio 或其它 OpenAI 兼容接口，客户端一般填：

- API Host：`https://lm.ee2x.cn/v1`
- API Key：填写本地服务实际要求的 Token

如果服务未开启鉴权，而客户端又强制要求填写 Key，可先填任意占位字符串。

#### 6.1.6 发布后验证

至少按下面顺序验证一次：

1. 服务器端口是否可通

```bash
curl http://64.90.17.178:12345/v1/models
```

2. 子域名 HTTPS 是否可通

```bash
curl https://lm.ee2x.cn/v1/models
```

3. 手机客户端是否可通

- 将 App 的 API Host 改为 `https://lm.ee2x.cn/v1`
- 观察是否能拉到模型列表
- 实际发起一次对话或推理请求

#### 6.1.7 安全建议

如果子域名已经接入成功，建议后续不要继续让用户直接访问：

- `64.90.17.178:12345`

更推荐的做法是：

- 客户端统一只走 `https://lm.ee2x.cn`
- 服务器防火墙仅保留 `80/443`
- `12345` 仅用于 OpenResty 回源或运维排查
- 本地服务自身开启 Token 鉴权

## 7. 日常更新流程

### 7.1 小范围更新

适用于：

- 只改少量前端文件
- 只改少量后端文件
- 不需要整体重新上传整个项目

推荐步骤：

1. 本地完成代码修改
2. 先执行：

```powershell
pnpm -r lint
```

3. 将修改过的文件同步到服务器 `/opt/APP/lwai`
4. 在服务器执行：

```bash
cd /opt/APP/lwai
WEB_PORT=4000 SERVER_PORT=4001 PM2_WEB_NAME=lwai-web PM2_SERVER_NAME=lwai-server bash ./scripts/start-runtime-linux.sh
```

### 7.2 全量更新

适用于：

- 改动范围大
- 需要整体替换代码、脚本、样式、配置
- 需要同时带上数据库或 `storage`

推荐步骤：

1. 本地打包或整体上传
2. 先在服务器留存回滚备份
3. 覆盖 `/opt/APP/lwai`
4. 重新执行 Linux 启动脚本

## 11. 常见问题

### 11.1 SQLite 路径错误

现象：

- 后端启动报 Prisma `P2021`
- 找不到 `User` 表

原因：

- `DATABASE_URL` 写成了错误的相对路径

正确写法：

```env
DATABASE_URL="file:../dev.db"
```

### 11.2 本地或服务器脚本最后输出 `locked`

现象：

- 统一启动脚本最后的 `curl` 自检显示 `locked`
- 但 `pm2` 和公网访问都正常

处理：

- 优先以 `pm2 list`
- `https://lwai.ee2x.cn/`
- `https://lwai.ee2x.cn/api/health`

的真实结果为准。

### 11.3 前端客户端异常

如果出现：

- `Application error: a client-side exception has occurred`
- `Minified React error #185`

优先检查：

- 是否已完成新构建发布
- 浏览器是否缓存旧前端脚本
- 是否用无痕窗口复测

相关修复历史见：

- `进度快照/30-客户端会话订阅死循环修复.md`
